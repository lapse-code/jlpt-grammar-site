> 本节和 [[N2文法7项接口分类]] 使用同一套标准。  
> 这不是按中文意思分类，也不是按 JLPT 章节分类，而是按“后面的文法点要求前项变成什么接续入口”分类。

---

## 0. 为什么要用“接口”判断接续

日语文法接续最容易错的地方，不是动词怎么变形，而是：

> 同一个中文意思，日语后项要求的前项身份可能完全不同。

比如中文都可以说“应该”：

| 文法 | 例子 | 实际接续入口 |
|---|---|---|
| [[～はずだ｜应该～；按理说～]] | 来るはずだ | 前项修饰形式名词「はず」 |
| [[～べきだ｜应该～]] | 行くべきだ | 「べき」按助动词性规则接动词辞书形 |

所以不能只看中文意思。  
要先看后面的文法点在句子里像什么：

- 像名词吗？
- 像助词吗？
- 像引用结构吗？
- 像后缀吗？
- 已经指定了て形、た形、ない形吗？
- 是助动词系统吗？
- 是强逻辑关系吗？

这就是“接口分类”的目的。

## 1. 七项接口总览

| 接口分类 | 数量 | 一句话判断 | 典型入口 |
|---|---:|---|---|
| 连体修饰 / 形式名词接口 | 70 | 后项像名词，前项要像“……的”一样修饰它 | わけ、はず、もの、こと、ところ、ため、場合 |
| 名词短语 / 格助词接口 | 168 | 后项像助词或复合助词，前项通常要是名词短语 | に、を、から、について、に対して、によって |
| 完整句子 / 引用接口 | 61 | 后项接一整个命题，前项要能独立成句 | と、という、か、かどうか |
| 连用形 / 词干接口 | 54 | 后项像后缀，前项用ます形去ます或词干 | 得る、かねる、がち、がたい、そうだ・様態 |
| 指定活用接口 | 75 | 文法点已经指定て、た、ない、ば、ず、意向形等 | て、た、ない、ば、ず、ようと |
| 助动词选择接口 | 28 | 后项有自己的助动词性接续规则，不能统一套一种接口 | べき、まい、よう、らしい、かもしれない |
| 条件 / 逻辑关系接口 | 25 | 后项核心是条件、让步、既然、无论、除非等逻辑关系 | からには、以上は、としても、にせよ、限り |

注意：

> 一个文法点可能同时有多个特征。  
> 本库采用“主入口分类”：优先选择最能帮助造句、最能避免接续错误的那个入口。

## 2. 连体修饰 / 形式名词接口

### 2.1 什么时候使用这一类

如果后面的文法点本身像一个名词，前面的内容要去修饰它，就属于这一类。

典型后项包括：

- わけ
- はず
- もの
- こと
- ところ
- ため
- 場合
- うち
- 間
- 末

这种结构的感觉是：

> 前项 + 的 + 后项

比如：

```md
彼が来るはずだ
```

可以理解成：

> “他会来”这个应然性 / 可能性

这里的 `来る` 不是被引用，而是在修饰后面的形式名词 `はず`。

### 2.2 典型接续

| 前项 | 常见形式 | 例子 |
|---|---|---|
| 動詞 | 普通形 | 来るはずだ、行ったところだ |
| い形容詞 | 普通形 | 高いはずだ、早いものだ |
| な形容詞 | な | 静かなはずだ、便利な場合 |
| 名詞 | の / な / である，按具体文法决定 | 学生のはずだ、学生である以上 |

这里要小心：名词和な形容词最容易错。  
不是所有形式名词前面都统一接 `の`，具体要看该文法点本身。

### 2.3 本库中的例子

| 文法 | 为什么属于这一类 |
|---|---|
| [[～わけだ｜也就是说～；难怪～]] | `わけ` 是形式名词，前项说明“道理 / 理由” |
| [[～はずだ｜应该～；按理说～]] | `はず` 是形式名词，前项修饰“按理应成立的内容” |
| [[～ものだ｜真是～；理应～；过去常常～]] | `もの` 保留形式名词性质，前项作连体修饰 |
| [[～ために｜为了～；因为～]] | `ため` 是形式名词，前项修饰“目的 / 原因” |
| [[～場合｜在～情况下]] | `場合` 是名词，前项修饰“情况” |

### 2.4 识别方法

看到一个文法点时，可以问：

> 后面这个东西是不是本来就像名词？  
> 前面的内容是不是在修饰这个名词性东西？

如果答案是 yes，大概率就是连体修饰 / 形式名词接口。

### 2.5 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 名词短语 / 格助词接口 | 连体修饰是“前项修饰后面的名词”；名词短语接口是“前项本身作为名词去接助词” |
| 完整句子 / 引用接口 | 连体修饰没有明显的 `と／という／か` 命题包装；引用接口会把前项当作一个完整命题拿来引用 |
| 助动词选择接口 | [[～はずだ｜应该～；按理说～]] 是形式名词；[[～べきだ｜应该～]] 是助动词性表达，所以不放同一类 |

## 3. 名词短语 / 格助词接口

### 3.1 什么时候使用这一类

如果后面的文法点像助词、复合助词、名词性后缀，名词短语通常是它的原型入口，就属于这一类。

这里的“名词短语 / 格助词接口”不是说这一类**永远只能接名词**。  
它的意思是：

> 这个文法点的核心结构像 `N + 助词 / 复合助词 / 名词性后缀`，名词入口最典型。  
> 但有些表达语法化以后，也允许动词普通形、形容词普通形直接进入。

典型长相：

- N + によって
- N + について
- N + に対して
- N + をめぐって
- N + に関して
- N + だけ
- N + ばかり
- N + ほど
- N + まで

例：

```md
天気によって予定を変える。
```

`によって` 前面直接接 `天気` 这个名词短语。

### 3.2 如果前面不是名词怎么办

如果前面是句子，但后项要求名词短语，通常要先名词化。

| 原本内容 | 名词化后 | 用法 |
|---|---|---|
| 日本語を勉強する | 日本語を勉強すること | 勉強することについて話す |
| 彼が来る | 彼が来ること | 彼が来ることに関して確認する |
| 静かだ | 静かであること / 静かなこと | 静かであることが条件だ |

所以这一类的关键不是“能不能接句子”，而是：

> 最终送进后项之前，前项要不要变成名词性单位？

但是要注意：这只是多数 `N + 助词` 型表达的规则，不是这一类的绝对规则。

例如 [[～にすぎない｜只不过是～]] 虽然归在“名词短语 / 格助词接口”，但它的实际接续是：

- 名詞 ＋ にすぎない
- 動詞普通形 ＋ にすぎない
- い形容詞普通形 ＋ にすぎない
- な形容詞語幹／な形容詞である ＋ にすぎない

也就是说：

```md
知っているにすぎない
```

是自然的，不需要改成：

```md
× 知っていることにすぎない
```

后者语法上不是完全不能成立，但语感会变成“只不过是‘知道这件事’这一点”，比直接说 `知っているにすぎない` 更重、更名词化，不是这个文法最自然的基本接法。

### 3.3 本库中的例子

| 文法                    | 为什么属于这一类                    |
| --------------------- | --------------------------- |
| [[～によって｜由于～；根据～；通过～]] | `N + によって`，前项是原因、依据、手段等名词短语 |
| [[～について｜关于～]]         | `N + について`，前项是话题对象          |
| [[～に対して｜与～相对；对于～]]    | `N + に対して`，前项是对象或对立面        |
| [[～をめぐって｜围绕～]]        | `N + をめぐって`，前项是争论或动作围绕的对象   |
| [[～だけ｜只～；尽量～]]        | `だけ` 是副助词，前项被作为限定对象处理       |
| [[～にすぎない｜只不过是～]]      | `N + に` 是原型结构，但可直接接普通形谓语，表示“只是这个程度” |

### 3.4 识别方法

看到这类文法点时，重点看开头有没有这些东西：

```md
に、を、から、まで、だけ、ばかり、ほど、について、に対して、によって
```

如果有，而且前项自然是一个名词、名词短语、名词化内容，就优先考虑名词短语 / 格助词接口。

### 3.5 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 连体修饰 / 形式名词接口 | [[～ために｜为了～；因为～]] 有形式名词 `ため`，不是简单的 `N + に` |
| 条件 / 逻辑关系接口 | `Nにしても` 表面像名词接助词，但核心是“即使 / 无论”的让步逻辑，所以本库归逻辑类 |
| 完整句子 / 引用接口 | 如果后项是 `という` 或 `と` 包装命题，就不是普通名词短语接口 |

## 4. 完整句子 / 引用接口

### 4.1 什么时候使用这一类

如果后面的文法点需要前面是一个完整命题，或者通过 `と／という／か` 把前面的内容包装起来，就属于这一类。

典型标志：

- と
- という
- か
- かどうか
- とされる
- と考えられる
- ということだ
- というものだ

例：

```md
彼は来月帰国するということだ。
```

`彼は来月帰国する` 是完整句子，后面用 `ということだ` 表示说明或传闻。

### 4.2 典型接续

| 前项 | 常见形式 | 例子 |
|---|---|---|
| 動詞 | 普通形 | 来るということだ |
| い形容詞 | 普通形 | 高いということだ |
| な形容詞 | だ / である，按文法决定 | 静かだということだ |
| 名詞 | だ / である，按文法决定 | 学生だということだ |

这类的重点是：

> 前项不是在修饰一个名词，而是作为一个完整判断被引用、说明、评价或疑问化。

### 4.3 本库中的例子

| 文法 | 为什么属于这一类 |
|---|---|
| [[～ということだ｜就是说～；听说～]] | `という` 引用前面的完整命题 |
| [[～と考えられる｜可以认为～]] | `と` 把前项作为判断内容 |
| [[～と思われる｜被认为～；看来～]] | `と` 标记被认为的命题 |
| [[～かどうか｜是否～]] | `かどうか` 把前项变成“是否成立”的命题 |
| [[～そうだ・伝聞｜听说～]] | 传闻 `そうだ` 接完整普通形命题，所以按本库归完整句子入口 |

### 4.4 识别方法

看到文法点里有：

```md
と、という、か、かどうか
```

先考虑完整句子 / 引用接口。

尤其是名词和な形容词：

```md
学生だと思う
静かだということだ
学生であると考えられる
```

这里不能写成：

```md
× 学生のと思う
× 静かなということだ
```

因为它要的不是“修饰名词”，而是完整判断。

### 4.5 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 连体修饰 / 形式名词接口 | `来るはずだ` 是修饰 `はず`；`来るということだ` 是引用“来る”这个命题 |
| 助动词选择接口 | [[～かもしれない｜也许～；可能～]] 接完整命题，但它本身是判断助动词性表达，本库归助动词选择接口 |
| 连用形 / 词干接口 | [[～そうだ・様態｜看起来～；似乎要～]] 接词干，不接完整命题，所以不和传闻 `そうだ` 同类 |

## 5. 连用形 / 词干接口

### 5.1 什么时候使用这一类

如果后面的文法点像后缀、复合动词、复合形容词、倾向表达，前面通常用动词ます形去掉 `ます`，或形容词词干，就属于这一类。

典型形式：

```md
動詞ます形去ます + 后项
い形容詞词干 + 后项
な形容詞词干 + 后项
```

例：

```md
起こり得る
起こりかねない
忘れがちだ
食べきる
高そうだ
静かそうだ
```

### 5.2 本库中的例子

| 文法 | 接续入口 |
|---|---|
| [[～得る｜可能～]] | 動詞ます形去ます + 得る |
| [[～得ない｜不可能～]] | 動詞ます形去ます + 得ない |
| [[～かねない｜很可能会～；恐怕会～]] | 動詞ます形去ます + かねない |
| [[～かねる｜难以～；不能～]] | 動詞ます形去ます + かねる |
| [[～がち｜容易～；常常～]] | 動詞ます形去ます / 名詞 + がち |
| [[～そうだ・様態｜看起来～；似乎要～]] | Vます形去ます、いA词干、なA词干 + そうだ |

### 5.3 识别方法

看到以下后项时，优先检查是不是连用形 / 词干：

```md
得る、得ない、かねる、かねない、がち、がたい、づらい、にくい、やすい、すぎる、きる、ぬく、始める、終わる、そうだ・様態
```

判断重点：

> 前项能不能从 `ます形` 去掉 `ます` 后直接接上？

比如：

```md
起こります → 起こり + 得る
食べます → 食べ + きる
忘れます → 忘れ + がち
```

### 5.4 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 指定活用接口 | `食べている` 是て形；`食べきる` 是ます形去ます |
| 助动词选择接口 | 样态 `そうだ` 从词干进入，所以本库按连用形 / 词干；但 `べきだ` 不是词干接续，所以不放这里 |
| 名词短语接口 | 有些后缀也能接名词，如 `がち`，但主入口仍然是后缀化接续，要看具体文法 |

## 6. 指定活用接口

### 6.1 什么时候使用这一类

如果文法点已经明确指定前项要变成某个活用形，就属于这一类。

典型入口：

- て形
- た形
- ない形
- ば形
- ず形
- 意向形
- 受身形
- 使役形

这类不需要绕远路分析“它是不是名词”。  
看到指定形，就直接变形。

### 6.2 本库中的例子

| 文法 | 为什么属于这一类 |
|---|---|
| [[～ても｜即使～也～]] | `て` 已经要求前项是て形 |
| [[～たら｜如果～；一～就～]] | `たら` 来自た形 + ら |
| [[～ないわけにはいかない｜不能不～]] | 前项明确是否定形 |
| [[～ば｜如果～]] | 前项必须变成ば形 |
| [[～ずにはいられない｜不由得～；忍不住～]] | 前项用ない形去ない + ず |
| [[～ようとする｜正要～；试图～]] | 前项用意向形 |

### 6.3 识别方法

先看文法点开头或核心位置有没有这些形态：

```md
て、た、ない、ば、ず、ようと、れる、られる、せる、させる
```

如果有，通常优先按指定活用接口处理。

### 6.4 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 条件 / 逻辑关系接口 | `ば`、`たら` 有条件意思，但入口形态太明确，所以本库归指定活用 |
| 连体修饰接口 | `たところだ` 里面有 `ところ`，但入口先指定た形，所以本库归指定活用 |
| 完整句子接口 | `ようと思う` 前面是意向形，不是普通完整句，所以不要只看后面的 `と思う` |

---

## 7. 助动词选择接口

### 7.1 什么时候使用这一类

如果后项本身像助动词或判断助动词性表达，而且它会根据词类选择自己的接续规则，就属于这一类。

这一类不能简单套：

- 形式名词规则
- 名词短语规则
- 引用规则
- 连用形规则

必须看它自己的规则。

### 7.2 本库中的例子

| 文法 | 接续特点 |
|---|---|
| [[～べきだ｜应该～]] | 主要接動詞辞書形；する可变成するべき / すべき |
| [[～まい｜不会～；绝不～]] | 按动词类别有自己的接续规则 |
| [[～かもしれない｜也许～；可能～]] | 接普通形命题，但作为判断助动词性表达处理 |
| [[～に違いない｜一定～；肯定～]] | 对前项命题作强判断，接续按自身规则处理 |
| [[～ように｜为了能～；请～；希望～]] | `よう` 系表达有自己的接续和功能分化 |

### 7.3 为什么不是所有助动词名字都放这里

本库按“主入口”分类，不按词典标签分类。  
所以有些看起来像助动词的东西，会根据实际接续被放到别的类。

| 文法 | 本库分类 | 原因 |
|---|---|---|
| [[～そうだ・伝聞｜听说～]] | 完整句子 / 引用接口 | 传闻 `そうだ` 接完整普通形命题 |
| [[～そうだ・様態｜看起来～；似乎要～]] | 连用形 / 词干接口 | 样态 `そうだ` 接Vます形去ます、いA词干、なA词干 |
| [[～はずだ｜应该～；按理说～]] | 连体修饰 / 形式名词接口 | `はず` 是形式名词，不是 `べき` 那种助动词性规范判断 |
| [[～べきだ｜应该～]] | 助动词选择接口 | `べき` 自身决定接续，表达义务或规范 |

### 7.4 识别方法

遇到以下后项时，不要急着套普通规则：

```md
べき、まい、よう、らしい、かもしれない、に違いない、に決まっている
```

先问：

> 这个后项是不是自己规定动词、い形容词、な形容词、名词的接续？

如果是，就按助动词选择接口处理。

## 8. 条件 / 逻辑关系接口

### 8.1 什么时候使用这一类

如果文法点的核心不是某个词类接续，而是把前后句绑定成强逻辑关系，就属于这一类。

典型逻辑包括：

- 既然～就～
- 即使～也～
- 无论～还是～
- 只要～就～
- 除非～否则～
- 如果能～的话
- 没有～就不能～

### 8.2 本库中的例子

| 文法 | 逻辑关系 |
|---|---|
| [[～からには｜既然～就～]] | 前项是既成前提，后项是应有结果 |
| [[～以上は｜既然～就～]] | 前项成立后，后项成为责任或必然判断 |
| [[～としても｜即使～也～；即使作为～也～]] | 让步条件 |
| [[～にしても｜即使～也～；无论～还是～]] | 让步或列举条件 |
| [[～にせよ｜即使～也～]] | 让步条件 |
| [[～限り｜只要～；在～范围内]] | 条件或范围 |
| [[～ものなら｜如果能～的话；要是～的话]] | 假设条件，常带难以实现感 |

### 8.3 识别方法

看到这些意义时，要警惕它可能不是普通词类接口：

```md
既然、即使、无论、只要、除非、要是、如果能、没有……就不能
```

这类文法点要重点看前后句的逻辑绑定。

### 8.4 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 指定活用接口 | [[～ば｜如果～]] 和 [[～たら｜如果～；一～就～]] 有条件意义，但接续形态明确，所以归指定活用 |
| 名词短语接口 | [[～にしても｜即使～也～；无论～还是～]] 表面有 `に`，但核心是让步逻辑，所以归逻辑类 |
| 连体修饰接口 | [[～限り｜只要～；在～范围内]] 表面像形式名词，但核心是条件 / 范围逻辑，所以归逻辑类 |

## 9. 七类之间的边界判断

### 9.1 连体修饰 vs 名词短语

| 判断问题 | 连体修饰 / 形式名词 | 名词短语 / 格助词 |
|---|---|---|
| 后项像什么 | 形式名词 | 助词、复合助词、副助词 |
| 前项在做什么 | 修饰后项 | 作为名词性对象接助词 |
| 例子 | [[～はずだ｜应该～；按理说～]]、[[～ために｜为了～；因为～]] | [[～によって｜由于～；根据～；通过～]]、[[～について｜关于～]] |

判断句：

> 如果是“前项 + 的 + 后项”，偏连体修饰。  
> 如果是“名词 + 助词 / 复合助词”，偏名词短语。

### 9.2 连体修饰 vs 完整句子 / 引用

| 判断问题 | 连体修饰 | 完整句子 / 引用 |
|---|---|---|
| 前项身份 | 修饰名词的内容 | 一个完整命题 |
| 标志 | わけ、はず、もの、ところ | と、という、か |
| 例子 | 来るはずだ | 来るということだ |

关键区别：

```md
来るはずだ
```

这里 `来る` 修饰 `はず`。

```md
来るということだ
```

这里 `来る` 被 `という` 引用成一个命题。

### 9.3 完整句子 / 引用 vs 助动词选择

| 判断问题 | 完整句子 / 引用 | 助动词选择 |
|---|---|---|
| 主要标志 | と、という、か | べき、まい、よう、かもしれない 等 |
| 判断重点 | 前项作为命题被引用 | 后项自身规定接续和判断意义 |
| 例子 | [[～と考えられる｜可以认为～]] | [[～かもしれない｜也许～；可能～]] |

注意：

> 接完整普通形不一定都归“完整句子 / 引用”。  
> 如果后项本身是判断助动词性表达，本库可能归“助动词选择接口”。

### 9.4 连用形 / 词干 vs 指定活用

| 判断问题 | 连用形 / 词干 | 指定活用 |
|---|---|---|
| 前项形态 | ます形去ます、词干 | て形、た形、ない形、ば形、ず形、意向形 |
| 例子 | 食べきる、起こり得る | 食べても、食べたら、食べないことには |

判断句：

> 如果是 `食べます → 食べ + 后项`，就是连用形 / 词干。  
> 如果是 `食べて、食べた、食べない、食べれば`，就是指定活用。

### 9.5 指定活用 vs 条件 / 逻辑关系

| 判断问题 | 指定活用 | 条件 / 逻辑关系 |
|---|---|---|
| 主要判断 | 前项形态被明确指定 | 前后句构成强逻辑框架 |
| 例子 | [[～ば｜如果～]]、[[～たら｜如果～；一～就～]] | [[～からには｜既然～就～]]、[[～としても｜即使～也～；即使作为～也～]] |

所以：

```md
～ば
～たら
～ても
```

虽然有条件或让步意思，但因为入口形态明确，本库优先归指定活用。

```md
～からには
～としても
～にせよ
```

则因为逻辑框架更强，归条件 / 逻辑关系。

### 9.6 助动词选择 vs 其他接口

| 文法 | 不归同类的原因 |
|---|---|
| [[～はずだ｜应该～；按理说～]] vs [[～べきだ｜应该～]] | 中文都可译“应该”，但 `はず` 是形式名词，`べき` 是规范判断助动词性表达 |
| [[～そうだ・伝聞｜听说～]] vs [[～そうだ・様態｜看起来～；似乎要～]] | 传闻接完整命题，样态接词干，所以本库拆开分类 |
| [[～ようだ｜好像～；像～一样]] vs [[～ように｜为了能～；请～；希望～]] | 都含 `よう`，但功能和接续入口不同，要看具体条目 |

## 10. 实际判断流程

### Step 1：先看现成分类

如果这个文法点已经在本库里，优先看该笔记 `## 接续` 下方的这一行：

```md
> 接口分类：[[N2文法7项接口分类]]：某某接口
```

这是当前库的标准分类。

### Step 2：如果是新文法，先找“入口长相”

| 入口长相 | 优先考虑 |
|---|---|
| わけ、はず、もの、こと、ところ、ため、場合 | 连体修饰 / 形式名词接口 |
| に、を、から、まで、について、に対して、によって | 名词短语 / 格助词接口 |
| と、という、か、かどうか | 完整句子 / 引用接口 |
| 得る、かねる、がち、がたい、きる、ぬく、そうだ・様態 | 连用形 / 词干接口 |
| て、た、ない、ば、ず、ようと | 指定活用接口 |
| べき、まい、よう、らしい、かもしれない、に違いない | 助动词选择接口 |
| からには、以上は、としても、にせよ、限り、ものなら | 条件 / 逻辑关系接口 |

### Step 3：问“前项要变成什么身份”

| 后项需要什么 | 前项怎么处理 |
|---|---|
| 修饰名词 | 用连体修饰形 |
| 名词性对象 | 用名词、名词短语、こと / の名词化 |
| 完整命题 | 保留完整普通形，名词 / な形容词注意だ / である |
| 后缀连接 | 用Vます形去ます或词干 |
| 特定活用形 | 直接变て、た、ない、ば、ず、意向形等 |
| 助动词规则 | 查该助动词自己的接续 |
| 逻辑前提 / 条件 / 让步 | 看前项如何构成成立判断或条件框架 |

### Step 4：重点检查名词和な形容词

动词和い形容词通常比较稳定。  
最容易错的是名词和な形容词。

| 需要的身份 | な形容词 | 名词 |
|---|---|---|
| 修饰形式名词 | 静かな | 学生の / 学生である，按文法决定 |
| 完整命题 | 静かだ / 静かである | 学生だ / 学生である |
| 名词短语 | 静かさ / 静かなこと | 学生 |
| 词干接后缀 | 静かそう | 通常不直接按词干处理，按具体文法判断 |
| 条件 | 静かなら | 学生なら |

## 11. 最终压缩版

日语文法接续判断的核心不是：

> 这个中文意思是什么？

而是：

> 后面的文法点要求前面的内容变成什么语法身份？

七类接口可以压缩成这样：

| 接口 | 核心问题 |
|---|---|
| 连体修饰 / 形式名词接口 | 前项是不是在修饰后面的形式名词？ |
| 名词短语 / 格助词接口 | 前项是不是要作为名词性对象去接助词？ |
| 完整句子 / 引用接口 | 前项是不是一个完整命题，被 `と／という／か` 引用或包装？ |
| 连用形 / 词干接口 | 前项是不是用ます形去ます或词干去接后缀？ |
| 指定活用接口 | 后项是不是已经指定て、た、ない、ば、ず、意向形？ |
| 助动词选择接口 | 后项是不是有自己的助动词性接续规则？ |
| 条件 / 逻辑关系接口 | 前后句是不是被绑定成条件、让步、既然、无论、除非等逻辑关系？ |

一句话总结：

> **接续不是背词类清单，而是判断接口形状。先看后项需要什么，再把前项变成对应身份。**
