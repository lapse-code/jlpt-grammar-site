## 0. 为什么要用“接口”判断接续

日语文法接续最容易错的地方，不是动词怎么变形，而是：

> 同一个中文意思，日语后项要求的前项身份可能完全不同。

比如中文都可以说“应该”：

| 文法 | 例子 | 实际接续入口 |
|---|---|---|
| [[～はずだ｜应该～；按理说～]] | 来るはずだ | 前项修饰形式名词「はず」 |
| [[～べきだ｜应该～]] | 行くべきだ | 「べき」按助动词性规则接动词辞书形 |

所以不能只看中文意思。  
要先看后面的文法点在句子里像什么：

- 像名词吗？
- 像助词吗？
- 像引用结构吗？
- 像后缀吗？
- 已经指定了て形、た形、ない形吗？
- 是助动词系统吗？
- 是强逻辑关系吗？

这就是“接口分类”的目的。

## 1. 七项接口总览

| 接口分类 | 数量 | 一句话判断 | 典型入口 |
|---|---:|---|---|
| 连体修饰 / 形式名词接口 | 73 | 后项像名词，前项要像“……的”一样修饰它 | わけ、はず、もの、こと、ところ、ため、場合 |
| 助词性接口 | 178 | 后项像助词、复合助词、副助词或助词化表达；接续要按具体助词类型判断 | に、を、から、だけ、ばかり、なくしては、なしには、にしても、にせよ、にしろ、について、に対して、によって |
| 完整句子 / 引用接口 | 54 | 后项接一整个命题，前项要能独立成句 | と、という、か、かどうか、としても |
| 连用形 / 词干接口 | 55 | 后项像后缀，前项用ます形去ます或词干 | 得る、かねる、がち、がたい、っこない、そうだ・様態 |
| 指定活用接口 | 80 | 文法点已经指定て、た、ない、ば、ず、可能形、意向形等 | て、た、ない、ば、ず、可能形、意向形、ようと思う、ものなら |
| 助动词选择接口 | 32 | 后项有自己的助动词性接续规则，不能统一套一种接口 | べき、まい、まいと思う、よう、ようなら、ようでは、らしい、かもしれない |
| 条件 / 逻辑关系接口 | 9 | 后项核心是既成事实、范围前提或强逻辑关系；但若前项被明确指定活用、由助动词规则决定，或属于稳定助词化表达，则优先按对应接口处理 | からには、以上は、上は、限り、ならともかく |

注意：

> 一个文法点可能同时有多个特征。  
> 本库采用“主入口分类”：优先选择最能帮助造句、最能避免接续错误的那个入口。

## 3. 七类之间的边界判断

### 3.1 连体修饰 vs 助词性接口

| 判断问题 | 连体修饰 / 形式名词 | 助词性接口 |
|---|---|---|
| 后项像什么 | 形式名词 | 助词、复合助词、副助词 |
| 前项在做什么 | 修饰后项 | 按助词性表达要求进入；可能是名词，也可能是普通形、连体形、数量词 |
| 例子 | [[～はずだ｜应该～；按理说～]]、[[～ために｜为了～；因为～]] | [[～によって｜由于～；根据～；通过～]]、[[～について｜关于～]] |

判断句：

> 如果是“前项 + 的 + 后项”，偏连体修饰。  
> 如果核心后项是助词、复合助词、副助词或助词化表达，偏助词性接口。  
> 但进入助词性接口以后，还要继续判断它是否真的要求名词化。

### 3.2 连体修饰 vs 完整句子 / 引用

| 判断问题 | 连体修饰 | 完整句子 / 引用 |
|---|---|---|
| 前项身份 | 修饰名词的内容 | 一个完整命题 |
| 标志 | わけ、はず、もの、ところ | と、という、か |
| 例子 | 来るはずだ | 来るということだ |

关键区别：

```md
来るはずだ
```

这里 `来る` 修饰 `はず`。

```md
来るということだ
```

这里 `来る` 被 `という` 引用成一个命题。

`こと` 本身并不自动等于“完整句子 / 引用接口”。

```md
雨が降ったことから、道路が濡れている。
試験も終わったことだし、少し休もう。
```

这里的 `こと` 是形式名词，前项是在修饰 `こと`，所以 [[～ことから｜由于～；从～来看]] 和 [[～ことだし｜也因为～，所以～]] 归入连体修饰 / 形式名词接口。

```md
雨が降ったということから、予定を変更した。
```

这里多了 `という`，前项先被包装成“雨が降った这一命题 / 这一事实”，所以 [[～ということから｜由于～这一点]] 归入完整句子 / 引用接口。

### 3.3 完整句子 / 引用 vs 助动词选择

| 判断问题 | 完整句子 / 引用 | 助动词选择 |
|---|---|---|
| 主要标志 | と、という、か | べき、まい、よう、かもしれない 等 |
| 判断重点 | 前项作为命题被引用 | 后项自身规定接续和判断意义 |
| 例子 | [[～と考えられる｜可以认为～]] | [[～かもしれない｜也许～；可能～]] |

注意：

> 接完整普通形不一定都归“完整句子 / 引用”。  
> 如果后项本身是判断助动词性表达，本库可能归“助动词选择接口”。

### 3.4 连用形 / 词干 vs 指定活用

| 判断问题 | 连用形 / 词干 | 指定活用 |
|---|---|---|
| 前项形态 | ます形去ます、词干 | て形、た形、ない形、ば形、ず形、意向形 |
| 例子 | 食べきる、起こり得る | 食べても、食べたら、食べないことには |

判断句：

> 如果是 `食べます → 食べ + 后项`，就是连用形 / 词干。  
> 如果是 `食べて、食べた、食べない、食べれば`，就是指定活用。

### 3.5 指定活用 vs 条件 / 逻辑关系

| 判断问题 | 指定活用 | 条件 / 逻辑关系 |
|---|---|---|
| 主要判断 | 前项形态被明确指定 | 前后句构成强逻辑框架 |
| 例子 | [[～ば｜如果～]]、[[～たら｜如果～；一～就～]]、[[～ない限り｜除非～否则不～]] | [[～からには｜既然～就～]]、[[～以上は｜既然～就～]] |

所以：

```md
～ば
～たら
～ても
～ない限り
～さえ～ば
```

虽然有条件或让步意思，但因为入口形态明确，本库优先归指定活用。

```md
～からには
～以上は
～限り
```

则因为逻辑框架更强，归条件 / 逻辑关系。

注意：[[～としても｜即使～也～；即使作为～也～]] 的语义也是让步，但主接续是 `普通形／だ＋としても`，前项先作为完整命题被 `と` 接住，所以本库归 **完整句子 / 引用接口**。

同理，[[～にせよ｜即使～也～]]、[[～にしろ｜即使～也～]] 语义也是让步，但主入口是 `に` 系助词化固定表达，所以本库归 **助词性接口**。

### 3.6 助动词选择 vs 其他接口

| 文法 | 不归同类的原因 |
|---|---|
| [[～はずだ｜应该～；按理说～]] vs [[～べきだ｜应该～]] | 中文都可译“应该”，但 `はず` 是形式名词，`べき` 是规范判断助动词性表达 |
| [[～そうだ・伝聞｜听说～]] vs [[～そうだ・様態｜看起来～；似乎要～]] | 传闻接完整命题，样态接词干，所以本库拆开分类 |
| [[～ようだ｜好像～；像～一样]] vs [[～ように｜为了能～；请～；希望～]] | 都含 `よう`，但功能和接续入口不同，要看具体条目 |

## 4. 实际判断流程

### Step 1：先看现成分类

如果这个文法点已经在本库里，优先看该笔记 `## 接续` 下方的这一行：

```md
> 接口分类：[[N2文法7项接口分类]]：某某接口
```

这是当前库的标准分类。

### Step 2：如果是新文法，先找“入口长相”

| 入口长相 | 优先考虑 |
|---|---|
| わけ、はず、もの、こと、ところ、ため、場合 | 连体修饰 / 形式名词接口 |
| に、を、から、まで、だけ、ばかり、ほど、こそ、にしても、にせよ、にしろ、について、に対して、によって | 助词性接口 |
| と、という、か、かどうか、としても | 完整句子 / 引用接口 |
| 得る、かねる、がち、がたい、きる、ぬく、っこない、そうだ・様態 | 连用形 / 词干接口 |
| て、た、ない、ば、ず、可能形、意向形、ようと思う、ものなら | 指定活用接口 |
| べき、まい、まいと思う、よう、ようなら、ようでは、らしい、かもしれない、に違いない | 助动词选择接口 |
| からには、以上は、上は、限り、ならともかく | 条件 / 逻辑关系接口 |

### Step 3：问“前项要变成什么身份”

| 后项需要什么 | 前项怎么处理 |
|---|---|
| 修饰名词 | 用连体修饰形 |
| 助词性入口 | 先看二级类型：可能用名词、こと / の名词化、普通形、连体形、数量词或名词谓语 |
| 完整命题 | 保留完整普通形，名词 / な形容词注意だ / である |
| 后缀连接 | 用Vます形去ます或词干 |
| 特定活用形 | 直接变て、た、ない、ば、ず、意向形等 |
| 助动词规则 | 查该助动词自己的接续 |
| 逻辑前提 / 条件 / 让步 | 看前项如何构成成立判断或条件框架 |

### Step 4：重点检查名词和な形容词

动词和い形容词通常比较稳定。  
最容易错的是名词和な形容词。

| 需要的身份 | な形容词 | 名词 |
|---|---|---|
| 修饰形式名词 | 静かな | 学生の / 学生である，按文法决定 |
| 完整命题 | 静かだ / 静かである | 学生だ / 学生である |
| 助词性入口 | 静かさ / 静かなこと / 静かである，按助词类型决定 | 学生 / 学生である，按助词类型决定 |
| 词干接后缀 | 静かそう | 通常不直接按词干处理，按具体文法判断 |
| 条件 | 静かなら | 学生なら |

## 5. 最终压缩版

日语文法接续判断的核心不是：

> 这个中文意思是什么？

而是：

> 后面的文法点要求前面的内容变成什么语法身份？

七类接口可以压缩成这样：

| 接口 | 核心问题 |
|---|---|
| 连体修饰 / 形式名词接口 | 前项是不是在修饰后面的形式名词？ |
| 助词性接口 | 后项是不是助词、复合助词、副助词或助词化表达？它的二级接续要求是什么？ |
| 完整句子 / 引用接口 | 前项是不是一个完整命题，被 `と／という／か` 引用或包装？ |
| 连用形 / 词干接口 | 前项是不是用ます形去ます或词干去接后缀？ |
| 指定活用接口 | 后项是不是已经指定て、た、ない、ば、ず、可能形、意向形？ |
| 助动词选择接口 | 后项是不是有自己的助动词性接续规则？ |
| 条件 / 逻辑关系接口 | 前后句是不是被绑定成既成事实、范围前提或强逻辑框架，而且没有被其他接口更明确地决定？ |

一句话总结：

> **接续不是背词类清单，而是判断接口形状。先看后项需要什么，再把前项变成对应身份。**
