# 指定活用接口

## 1. 什么时候使用这一类

如果文法点已经明确指定前项要变成某个活用形，就属于这一类。

典型入口：

- て形
- た形
- ない形
- ば形
- ず形
- 可能形
- 意向形
- 受身形
- 使役形

这类不需要绕远路分析“它是不是名词”。  
看到指定形，就直接变形。

## 2. 本库中的例子

| 文法 | 为什么属于这一类 |
|---|---|
| [[～ても｜即使～也～]] | `て` 已经要求前项是て形 |
| [[～たら｜如果～；一～就～]] | `たら` 来自た形 + ら |
| [[～ないわけにはいかない｜不能不～]] | 前项明确是否定形 |
| [[～ば｜如果～]] | 前项必须变成ば形 |
| [[～ずにはいられない｜不由得～；忍不住～]] | 前项用ない形去ない + ず |
| [[～ない限り｜除非～否则不～]] | 前项必须进入ない形，虽然语义是“除非”也优先按指定活用处理 |
| [[～さえ～ば｜只要～就～]] | 核心是 `さえ + ば形`，最低条件由ば形决定 |
| [[～ようとする｜正要～；试图～]] | 前项用意向形 |
| [[～ようと思う｜想要～]] | 前项用意向形，后面的 `と思う` 不是完整句子接口的主依据 |
| [[～ものなら｜如果能～的话；要是～的话]] | 前项指定为可能形或意向形，不能只按“如果”的语义处理 |
| [[～ものならば｜如果能～的话]] | 前项典型入口是可能形 + ものならば |

## 3. 识别方法

先看文法点开头或核心位置有没有这些形态：

```md
て、た、ない、ば、ず、可能形、意向形、ようと、れる、られる、せる、させる
```

如果有，通常优先按指定活用接口处理。

## 4. 容易混的边界

| 容易混的对象 | 区别 |
|---|---|
| 条件 / 逻辑关系接口 | `ば`、`たら`、[[～ない限り｜除非～否则不～]]、[[～さえ～ば｜只要～就～]]、[[～ものなら｜如果能～的话；要是～的话]] 有条件意思，但入口形态太明确，所以本库归指定活用 |
| 助词性接口 | [[～なくしては｜没有～就不能～]] 表面有 `なく`，但前项是名词 / こと名词化，不是把前项变成ない形，所以归助词性接口 |
| 连体修饰接口 | `たところだ` 里面有 `ところ`，但入口先指定た形，所以本库归指定活用 |
| 完整句子接口 | `ようと思う` 前面是意向形，不是普通完整句，所以不要只看后面的 `と思う` |
